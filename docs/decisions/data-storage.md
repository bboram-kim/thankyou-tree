# 데이터 저장소

## Decisions

- 트리와 오너먼트(배경을 지운 사진, 이름, 감사 메시지)는 Supabase Database와 Storage에 저장합니다. Supabase Auth는 쓰지 않습니다.
- 새 Supabase 프로젝트를 만들지 않고, 사용자가 이미 가진 기존 프로젝트를 함께 씁니다.
- 이 앱이 만드는 테이블, 함수, Storage 버킷은 기존 프로젝트의 객체와 이름이 겹치지 않아야 하고, 기존 객체와 데이터는 읽지도 바꾸지도 않습니다.

## Boundaries

- 기존 프로젝트의 다른 앱이 쓰는 스키마, 정책, 버킷은 이 앱의 작업 범위가 아닙니다.

## Why

Supabase 무료 플랜은 동시에 켜 둘 수 있는 프로젝트가 2개이고, 사용자는 기존 프로젝트를 정지하는 대신 함께 쓰기로 했습니다. 한 프로젝트에 다른 앱의 데이터가 같이 있으므로, 이름을 구분하고 서로 건드리지 않는 것이 함께 쓰는 조건입니다.

## Reconsider when

- 기존 프로젝트를 지우거나 정지해야 할 때
- 유료 플랜으로 바꾸거나 무료 프로젝트 자리가 생겨 따로 둘 수 있을 때

## Still-rejected alternatives

- 안 쓰는 프로젝트를 정지하고 새 프로젝트 만들기 — 데이터가 섞이지 않지만 사용자가 기존 프로젝트를 그대로 두길 원했습니다.
- 개발 서버 컴퓨터에 파일로 저장 — 준비가 필요 없지만 실제로 링크를 공유해 쓸 수 없어 결국 저장소를 다시 바꿔야 합니다.
