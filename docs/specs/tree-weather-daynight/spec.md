# 트리에 주인 지역의 날씨와 낮밤 반영

트리 주인이 사는 곳의 지금 날씨(맑음, 흐림, 비, 눈)가 트리 배경에 나타나고, 해가 지면 트리 전구가 켜지면서 트리에 딸린 화면 전체가 밤 색으로 어두워집니다.

- 제품 전제: [PRODUCT.md](../../../PRODUCT.md)의 "트리는 트리 주인이 사는 지역을 기준으로 지금 날씨와 낮밤을 반영합니다. 해가 지면 트리 전구가 켜집니다."와 경험 원칙 "열 때마다 살아 있는 장소처럼". 이 스펙은 그 경계를 처음 구현한다.
- [ui-composition](../../decisions/ui-composition.md): 트리 장면은 직접 그리는 핵심 표면이고, 그 밖의 일반 UI는 기존 semantic token과 shadcn component를 쓴다. 밤 화면도 새 색을 만들지 않고 프로젝트의 기존 다크 토큰을 쓴다.
- [prototype.html](prototype.html): 승인된 화면(방문자 트리, 내 트리와 메시지 시트, 트리 만들기). 트리 장면의 배경 연출(안개와 역광, 채도 낮은 하늘, 필름 질감, 비네팅), 날씨·낮밤 8가지 상태의 색과 입자, 밤의 트리 색 보정과 전구, 페이지 밤 색, 위치 안내 문구를 정한다. 구현은 이 화면을 기준으로 맞춘다.
- [data-storage](../../decisions/data-storage.md): 트리 지역을 저장할 때 기존 Supabase 프로젝트의 다른 객체를 건드리지 않는다.
- [owner-access](../../decisions/owner-access.md): 방문자 쪽에 나가는 정보의 경계. 주인의 위치가 방문자에게 드러나지 않아야 한다.

## 사용자에게 보이는 결과

- 트리 주인이 트리를 만들 때 위치를 한 번 허락하면, 이후 그 트리는 주인이 있던 곳의 날씨와 낮밤으로 보인다.
- 방문자와 주인은 링크를 열 때마다 주인 동네의 지금 하늘을 본다. 눈이 오면 눈이 내리고, 비가 오면 비가 내리고, 흐리면 구름이 끼고, 맑은 낮엔 해가 뜬다.
- 해가 지면 트리 전구가 켜지고 트리가 어두워지며, 제목과 버튼을 포함한 화면 전체가 밤 색으로 바뀐다. 맑은 밤에는 달과 별이 보인다.

## 범위

- 트리 만들기에서 주인 위치를 받아 트리의 지역으로 저장하기(거절하거나 받지 못하면 서울)
- 기상청 단기예보 조회서비스의 초단기예보로 지역의 지금 날씨 가져오기
- 지역의 일출·일몰로 낮밤 정하기
- 트리 장면의 배경을 프로토타입의 "안개와 역광" 연출로 바꾸기(트리 모양은 그대로, 장면의 빛에 맞춘 색 보정만)
- 트리 장면의 날씨 연출, 밤 밝기, 전구
- 트리에 딸린 화면의 밤 색 전환

## 수용 기준

**지역 정하기**

- AC1. 트리 만들기에서 "트리 만들기"를 누르면 브라우저가 위치 권한을 묻는다. 묻기 전에 이름 입력칸 아래에 "트리에 내 동네의 날씨와 낮밤을 담으려고, 만들 때 위치를 한 번 물어봐요. 정확한 위치는 저장하지 않아요."가 보인다.
- AC2. 위치를 허락하면 그 위치가 속한 기상청 격자가 트리의 지역으로 저장되고, 트리가 만들어진다.
- AC3. 위치를 거절했거나, 일정 시간 안에 받지 못했거나, 기상청 격자 밖(국외 등)이면 트리 만들기는 막히지 않는다. 지역은 서울로 저장되고, 만든 직후 링크 화면에 "위치를 받지 못해 서울 날씨로 보여요" 취지의 한 줄이 보인다.
- AC4. 저장되는 것은 격자 번호뿐이다. 위도·경도 원값은 저장하지 않고, 방문자 화면과 그 응답에도 격자보다 정밀한 위치가 나가지 않는다.
- AC5. 이 기능 전에 만들어진 트리는 지역이 서울이다.

**날씨**

- AC6. 방문자 트리 화면, 오너먼트 달기의 위치 정하기 화면, 주인 화면의 트리 장면은 트리 지역의 지금 날씨를 아래처럼 그린다.

  | 기상청 값 | 트리 날씨 | 장면(세부는 prototype.html의 해당 상태) |
  | --- | --- | --- |
  | 강수형태 비, 빗방울 | 비 | 어두운 청회색 하늘, 흐릿한 구름 덩어리, 가늘고 긴 빗줄기 |
  | 강수형태 눈, 비/눈, 눈날림, 빗방울눈날림 | 눈 | 옅은 회보라 하늘, 작고 선명한 먼 눈송이와 크고 흐린 가까운 눈송이 |
  | 강수 없음 + 하늘상태 구름많음, 흐림 | 흐림 | 회색 하늘, 흐릿한 구름 덩어리가 천천히 흐름 |
  | 강수 없음 + 하늘상태 맑음 | 맑음 | 낮엔 지평선이 따뜻한 겨울 하늘과 번지는 햇빛, 밤엔 달과 별 |

  모든 날씨에서 트리 뒤로 빛이 번지고, 땅 가까이 안개가 깔리며, 장면 전체에 옅은 필름 질감과 가장자리 어둠(비네팅)이 있다.

- AC7. 날씨를 가져오지 못하면(키 오류, 응답 지연, 기상청 장애) 페이지는 평소처럼 열리고 장면은 맑음으로 그려진다. 낮밤은 날씨와 무관하게 그대로 반영된다.
- AC8. 사용자가 움직임 줄이기(`prefers-reduced-motion`)를 켜 두었으면 비와 눈은 멈춘 채로 보인다.

**낮밤과 밝기**

- AC9. 트리 지역의 오늘 일출 이후 일몰 전이면 낮, 그 밖은 밤이다.
- AC10. 밤이면 트리 장면의 하늘이 날씨별 밤 색으로 어두워지고, 트리 몸통은 낮보다 어둡게, 오너먼트 사진은 트리보다 덜 어둡게 보인다. 트리 전구가 켜져 반짝이고 꼭대기 별이 빛나며, 트리 아래로 따뜻한 빛이 안개에 번진다. 맑은 밤에는 달과 별이, 눈 오는 밤에는 달과 눈이 보인다. 낮에는 전구가 꺼져 있다. 장면 가장자리 어둠은 밤에 더 짙다.
- AC11. 밤이면 트리에 딸린 화면(방문자 트리, 오너먼트 달기 흐름 전체, 주인 화면과 메시지 보기) 전체가 프로젝트의 다크 토큰으로 바뀐다. 제목, 설명, 버튼, 입력칸, 메시지 카드가 다크 토큰으로 읽기 좋게 보여야 한다. 낮이면 지금과 같은 밝은 화면이다.
- AC12. 트리 만들기(홈) 화면은 트리 지역이 없으므로 낮밤 전환 대상이 아니고, 항상 밝은 화면이다.

## 확정된 제약과 이유

- 지역은 트리를 만들 때 브라우저 위치 권한으로 받는다(사용자 확정). 시·도 선택보다 정확하게 주인 동네를 담기 위해서다.
- 위치를 못 받으면 서울로 두고 만들기를 막지 않는다(사용자 확정). 방문자에게 링크를 보내기까지의 걸림돌을 늘리지 않기 위해서다.
- 위치는 기상청 5km 격자 번호로만 남긴다. 링크를 연 누구나 트리를 보므로, 주인의 정확한 위치가 남거나 새지 않게 한다.
- 트리 장면 배경은 프로토타입의 "안개와 역광"이다(사용자 확정). 언덕·집·구름 같은 도형 그림은 촌스럽다는 판단으로 버렸고, "깊고 영화 같은 빛" 방향의 세 안(안개와 역광, 빛줄기, 먼 도시의 보케) 중에서 골랐다.
- 밤에는 트리 장면만이 아니라 트리에 딸린 화면 전체가 어두워진다(사용자 확정, 장면만 어둡게 하는 안과 해질녘 단계를 더하는 안을 비교한 뒤 선택). 밤에 링크를 열었을 때 화면 전체가 주인의 밤처럼 느껴지게 하기 위해서다.
- 날씨 데이터는 공공데이터포털의 기상청 단기예보 조회서비스(초단기예보)를 쓴다(사용자 요청: 공공데이터). 한 번의 조회로 하늘상태(`SKY`)와 강수형태(`PTY`)를 함께 받을 수 있다.
- 인증키는 서버에서만 쓰고 브라우저로 내보내지 않는다.
- 같은 격자의 날씨는 30분 동안 다시 쓰고 기상청을 매번 부르지 않는다. 초단기예보가 30분 단위로 발표되고, 개발계정 하루 호출 한도가 정해져 있기 때문이다.

## 가정 (바꿔도 되는 기본값)

- 비/눈 섞임, 눈날림, 빗방울눈날림은 크리스마스 트리 분위기에 맞춰 "눈"으로 본다.
- 일출·일몰은 별도 API 없이 날짜와 격자 위치로 계산한다. 해질녘 단계는 두지 않고 일몰 시각에 바로 밤이 된다.
- 낮밤과 날씨는 페이지를 열 때 정해진다. 열어 둔 채 해가 져도 새로고침 전까지는 바뀌지 않는다.
- 트리를 만든 뒤 지역을 바꾸는 기능은 없다.
- 날씨를 글로 표시(예: "서울 · 눈")하지 않고 장면으로만 보여 준다.
- 프로토타입의 색 값과 입자 개수는 승인된 모습을 재현하기 위한 값이다. 실제 화면에서 같은 인상을 유지하는 범위의 미세 조정은 괜찮다. 밤 화면의 일반 UI 색은 프로젝트 다크 토큰을 쓴다.
- 트리 모양(삼각형 세 단, 별)은 바꾸지 않고, 장면의 빛에 맞춘 채도·밝기 보정만 한다. 사용자가 트리 모양 다듬기를 이번에는 고르지 않았다.

## 범위 밖

- 크리스마스 이후 새 오너먼트 달기 막기: 날씨와 별개인 변경이라 [follow-up](../../follow-ups/block-new-ornaments-after-christmas.md)에서 따로 다룬다.
- 기온, 미세먼지, 바람 같은 다른 날씨 요소: 이번 요청은 배경과 밝기다.
- 방문자 자신의 위치나 시간대 반영: 트리는 주인의 장소를 담는다.
- 사용자가 직접 다크 모드를 켜고 끄는 설정: 밤 전환은 주인 지역의 시간으로만 정한다.

## 남은 위험

- 기상청 초단기예보의 코드표(`SKY` 1·3·4, `PTY` 0–7)와 발표 시각(매시 30분 발표, 45분 이후 제공)은 공공데이터포털 활용 가이드 기준의 지식이다. 공공데이터포털 소개 페이지에는 코드표가 보이지 않아 이번 shaping에서 실제 응답으로 확인하지 못했다. 구현 시작 때 발급받은 키로 실제 응답을 한 번 받아 대조해야 한다.
- 기상청·공공데이터포털에는 공식 에이전트 스킬이나 `llms.txt`가 없다(아래 스택 정리 참고). 구현은 공공데이터포털의 활용 가이드 문서를 직접 읽어야 한다.
- 다크 토큰은 지금 정의만 있고 실제 화면에서 쓰인 적이 없다. 오너먼트 달기 흐름의 입력칸, Drawer, 경고 같은 component가 다크 토큰에서 읽기 어렵게 보일 수 있다.
- 큰 흐림 필터, 필름 질감, 움직이는 눈·비 입자가 오래된 휴대폰에서 버벅일 수 있다. 프로토타입은 데스크톱에서만 확인했다.
- 위치 권한은 HTTPS에서만 동작한다. 로컬 개발(`localhost`)에서는 되지만, 다른 기기에서 HTTP 주소로 열면 항상 서울로 저장된다.

## 스택 정리

- 기상청 단기예보 조회서비스(공공데이터포털): 공식 에이전트 스킬 없음, `llms.txt` 없음(`data.go.kr/llms.txt` 404, `apihub.kma.go.kr/llms.txt`는 준비 중 HTML). 결과: unavailable from an official source. skills.sh의 커뮤니티 후보 `*/k-skill@korea-weather`가 있으나 공식이 아니어서 설치하지 않았다. 다시 볼 때: 기상청이나 공공데이터포털이 공식 에이전트 문서를 내놓을 때.

## Setup before implementation

- 공공데이터포털 "기상청_단기예보 ((구)_동네예보) 조회서비스" 활용 신청과 인증키 발급: 지역 날씨를 가져오기 위해 필요. 완료 조건: 그 키로 `getUltraSrtFcst`를 브라우저나 curl에서 직접 호출했을 때 `resultCode` `00`과 `SKY`, `PTY` 항목이 담긴 응답이 온다.
- 배포 환경의 환경 변수에 위 인증키 등록: 배포된 앱에서도 날씨를 가져오기 위해 필요. 완료 조건: 호스팅 콘솔의 환경 변수 목록에 키 항목이 보인다.
