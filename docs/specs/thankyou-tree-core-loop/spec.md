# 감사 트리 핵심 흐름 한 바퀴

트리 주인이 트리를 만들어 링크를 받고, 방문자가 사진 오너먼트와 감사 한 줄을 원하는 위치에 달고, 트리 주인이 오너먼트를 눌러 메시지를 읽는 흐름을 처음부터 끝까지 한 번 돌게 한다.

연결된 자료:
- [PRODUCT.md](../../../PRODUCT.md) — 앱 전체 전제. 이 단위는 그중 핵심 흐름, 공개 범위, 방문자 무로그인 경계를 따른다.
- [GLOSSARY.md](../../../GLOSSARY.md) — 트리, 트리 주인, 방문자, 오너먼트, 감사 메시지의 정의.
- [prototype.html](prototype.html) — 승인된 화면 6개(트리 만들기, 링크 받기, 트리(방문자), 오너먼트 만들기, 위치 정하기, 내 트리(주인))의 구성, 문구, 상태. 화면 구성과 문구는 이 파일을 따른다. 동작은 이 spec이 정하며, 프로토타입의 검토용 장치(빈 사진 칸 더블클릭으로 예시 인물 넣기, 가짜 처리 지연)는 제품 동작이 아니다.
- [owner-access](../../decisions/owner-access.md) — 주인 링크로 트리 주인을 판별하는 규칙.
- [data-storage](../../decisions/data-storage.md) — 기존 Supabase 프로젝트를 함께 쓰는 조건.
- [ui-composition](../../decisions/ui-composition.md) — 트리 표면은 직접 만들고, 버튼, 입력, 카드, 경고, 대화상자, 토스트 같은 일반 UI는 공식 shadcn component로 구성하는 규칙.

## 사용자에게 보이는 결과

1. 트리 주인이 자기 이름을 적고 트리를 만들면, 공유 링크와 주인 링크를 받는다. 주인 링크를 따로 저장하라는 경고가 함께 보인다.
2. 방문자가 공유 링크를 열면 "OO의 트리"와 이미 달린 오너먼트 사진들이 보인다. 이름과 메시지는 보이지 않는다.
3. 방문자가 사진을 고르면 배경이 제거된 미리보기가 나오고, 마음에 들지 않으면 다른 사진을 고를 수 있다.
4. 방문자가 이름과 감사 한 줄을 적고, 오너먼트를 끌어서 원하는 위치에 놓은 뒤 확인을 거쳐 단다.
5. 트리 주인이 주인 링크로 트리를 열고 오너먼트를 누르면 사진, 보낸 사람 이름, 단 날짜, 감사 메시지가 보인다.

## 승인된 범위

- 트리 만들기와 두 링크 발급
- 방문자 트리 보기, 오너먼트 만들기(사진 선택, 배경 제거, 이름, 감사 한 줄), 위치 정하기, 달기
- 주인 트리 보기와 오너먼트별 메시지 읽기
- 빈 트리, 배경 제거 중, 배경 제거 실패 상태
- 휴대폰 화면 우선. 카카오톡 링크를 눌러 휴대폰에서 여는 상황이 기본이다.

## 수용 기준

모두 실행 중인 앱에서 실제 브라우저로 확인한다. 방문자와 주인은 서로 다른 브라우저 세션(예: 일반 창과 시크릿 창)으로 확인한다.

- AC1. 트리 만들기 화면에서 이름을 비우면 "트리 만들기"를 누를 수 없다. 이름은 최대 20자까지 입력된다.
- AC2. 이름을 적고 트리를 만들면 링크 받기 화면에 서로 다른 공유 링크와 주인 링크가 각각 복사 버튼과 함께 보이고, 주인 링크를 따로 저장하라는 경고가 보인다. 복사 버튼을 누르면 해당 링크가 클립보드에 들어가고 복사했다는 토스트가 뜬다.
- AC3. 공유 링크를 열면 "{주인 이름}의 트리"와 달린 오너먼트 수, 오너먼트 사진이 각자의 위치에 보인다. 오너먼트가 없으면 첫 번째로 달아 달라는 빈 상태 문구가 보인다.
- AC4. 공유 링크로 연 화면에서는 어떤 오너먼트의 보낸 사람 이름과 감사 메시지도 보이지 않고, 그 페이지가 받는 응답 데이터에도 들어 있지 않다. 공유 링크 화면이나 응답에서 주인 링크를 알아낼 수 없다.
- AC5. 오너먼트 만들기에서 사진을 고르면 처리 중 표시가 나온 뒤, 배경이 제거된 사진이 미리보기로 보인다. "다른 사진 고르기"로 다시 고를 수 있다.
- AC6. 배경 제거에 실패하면 다시 골라 달라는 오류가 보이고, 사진이 없는 상태로 돌아간다.
- AC7. 사진, 이름(1–20자), 감사 한 줄(1–60자)이 모두 있을 때만 "위치 정하기"를 누를 수 있다. 이름과 감사 한 줄 입력칸에는 글자 수와 "트리 주인만 볼 수 있어요" 안내가 보인다.
- AC8. 위치 정하기에서 내 오너먼트를 손가락(터치)과 마우스 모두로 끌어 트리 영역 안 아무 곳에나 놓을 수 있다. 끄는 동안 페이지가 스크롤되지 않는다. 트리 모양 밖의 배경도 놓을 수 있는 위치다.
- AC9. "여기에 달기"를 누르면 한 번 달면 옮기거나 지울 수 없다는 확인 창이 뜬다. "다시 정하기"는 위치 정하기로 돌아가고, "달기"를 누르면 방문자 트리로 돌아가 내 오너먼트가 놓은 위치에 보이고 달았다는 토스트가 뜬다.
- AC10. 단 오너먼트는 새로고침한 뒤에도, 다른 기기나 세션에서 공유 링크를 열어도 같은 위치에 보인다.
- AC11. 주인 링크를 열면 내 트리가 보이고, 오너먼트를 누르면 그 오너먼트의 사진, 보낸 사람 이름, 단 날짜, 감사 메시지가 아래에서 올라오는 창에 보인다. 닫기나 바깥을 누르면 닫힌다.
- AC12. 주인 링크로 연 트리에서 오너먼트가 없으면 공유 링크를 보내 보라는 빈 상태 문구와 "공유 링크 복사"가 보인다.
- AC13. 저장되는 사진은 배경이 제거된 사진뿐이고, 방문자가 고른 원본 사진은 서버에 저장되지 않는다.
- AC14. 화면 글꼴은 나눔고딕이다.

## 확정된 제약과 근거

- 트리 주인은 주인 링크로 판별하고 로그인하지 않는다. 바로 써 보는 소소한 이벤트라 가입 단계를 두지 않는다. 규칙은 [owner-access](../../decisions/owner-access.md)를 따른다. (사용자 확정)
- 데이터는 사용자의 기존 Supabase 프로젝트에 저장하고, 기존 객체와 이름이 겹치지 않게 하며 건드리지 않는다. 무료 플랜 프로젝트 2개 제한 때문이다. 조건은 [data-storage](../../decisions/data-storage.md)를 따른다. (사용자 확정)
- 방문자는 로그인 없이 이름만 적는다. (PRODUCT.md)
- 메시지와 보낸 사람 이름은 트리 주인만 본다. 화면에서 감추는 것만으로는 부족하고, 공유 링크 쪽에는 그 값이 전달되지 않아야 한다. (PRODUCT.md, AC4)
- 오너먼트 크기는 트리 폭의 15% 정도이고, 트리 모양 밖 배경에도 놓을 수 있으며, 달기 전에 확인 창을 거친다. (프로토타입 검토에서 사용자 확정)
- 글꼴은 나눔고딕이다. 나눔고딕은 400, 700, 800 굵기만 있으므로 제목, 버튼, 입력칸 이름표는 700을 쓴다. (사용자 확정)

## 가정 (바꿀 수 있음)

- 트리를 만들 때 주인은 이름(최대 20자)만 적고, 트리에는 "{이름}의 트리"로 보인다.
- 감사 메시지는 최대 60자, 방문자 이름은 최대 20자다.
- 한 번 단 오너먼트는 방문자도 주인도 옮기거나 지울 수 없다. 오너먼트끼리 겹쳐도 되고 개수 제한도 없다.
- 배경 제거는 방문자의 브라우저에서 한다. 그래야 원본 사진이 서버로 가지 않는다(AC13).
- 한 방문자가 오너먼트를 여러 개 달 수 있다.
- 주인 화면의 단 날짜는 "12월 2일" 같은 월일 형식이다.
- 이 단위는 로컬 개발 서버에서 두 브라우저 세션으로 확인한다. 배포는 이 단위의 수용 기준이 아니다.

## 범위 밖과 이유

- 날씨와 낮밤 반영, 트리 주인의 지역 설정: 핵심 흐름이 먼저 돌아야 의미가 있어 다음 단위로 미뤘다. (사용자 확정)
- 크리스마스 이후 달기 막기: 아래 미룬 결정 참고.
- 오너먼트 수정, 삭제, 신고: 한 번 달면 고정이라는 가정과 맞지 않고 이번 흐름에 필요 없다.
- 주인 링크 분실 시 되찾기, 로그인: [owner-access](../../decisions/owner-access.md)의 경계.
- 기존 Supabase 프로젝트의 다른 테이블, 정책, 버킷: [data-storage](../../decisions/data-storage.md)의 경계.
- 배포: 이 단위는 로컬에서 흐름을 확인하는 것이 목표다.

## 미룬 결정

- 크리스마스(12월 25일)가 지난 뒤 새 오너먼트 달기 막기. PRODUCT.md의 경계지만 이번 흐름을 확인하는 데는 필요 없다. 그동안의 임시 동작: 날짜와 관계없이 오너먼트를 달 수 있다(AC3–AC10). 다시 볼 때: 2026-12-10까지, 또는 날씨·낮밤 단위를 shaping할 때 중 먼저 오는 때.

## 남은 위험

- 배경 제거를 브라우저에서 하면 휴대폰, 특히 카카오톡 인앱 브라우저에서 처음 한 번 모델을 내려받고 처리하는 데 시간이 오래 걸리거나 메모리가 부족할 수 있다. 구현 때 카카오톡 인앱 브라우저나 휴대폰 크기 브라우저에서 처리 시간을 확인하고, 너무 느리면 처리 중 문구를 유지한 채 방식을 다시 정한다.
- 아이폰에서 고른 HEIC 사진은 브라우저에 따라 바로 읽히지 않을 수 있다. 실패하면 AC6의 오류로 처리된다.
- 주인 링크를 잃어버리면 메시지를 다시 볼 수 없다. 링크 받기 화면의 경고로만 대응한다.
- 기존 Supabase 프로젝트를 함께 쓰므로, 그 프로젝트가 일시정지되거나 삭제되면 이 앱도 멈춘다.

## Setup before implementation

- 함께 쓸 기존 Supabase 프로젝트 하나를 정하고 활성 상태로 둔다. 오너먼트 저장에 필요하다. 완료 조건: Supabase 대시보드에서 그 프로젝트가 Paused가 아닌 활성 상태로 보이고, 프로젝트 URL과 publishable(anon) 키를 확인할 수 있다.
